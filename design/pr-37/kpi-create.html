KPI pane, the plot picker and Create

This is a hand drawn mockup, not a screenshot. Nothing here has been through Revit. It is drawn from KpiPanel.cs, CreateWords.cs and PanelTheme.cs so the layout and the wording can be read before somebody spends an install on it.

It cannot show how Revit will render it. WPF metrics, the dockable pane's real width and the font Revit hands the pane are all outside what a browser can tell you. Treat the words as exact and the spacing as approximate.

What the drawing is showing

  • Three modes in one list. One plot is a tick, several are several ticks, and every plot is Select all. There is no free text box anywhere: a plot the model does not hold cannot be chosen, which is the rule PlotTicks enforces.
  • The count shows at all times, from PlotTicks.InWords, so nobody presses Create wondering how many plots are about to be added together.
  • Both plot sources are named when they disagree, from CreateWords.PlotSources. The light pane shows the disagreeing case and the dark pane the agreeing one. Neither list wins.
  • The reference shows each parameter's value beside its name, so the pick is made by looking at the value. The four values are the ones measured on sheet 010EA.
  • Two refusals are drawn, one per pane. The light pane has a plot whose two filled regions both hold an area, which the type name cannot settle, so the tool asks. The dark pane has two plots reading the same area, which is either two plots of one size or one region counted twice. Both refuse the write until a person answers.
  • The buttons are buttons rather than combo boxes, because this block is thrown away and built again on every change and a combo box carries its own item list across a redraw. The three text boxes do outlive the redraw and go through Reparented.

What it does not show

  • The pane after a successful write. The status line then reads the count of cells that really landed, read back off the output file, from CreateWords.Wrote.
  • 160 plots in the tick list. The list scrolls at PanelMetrics.ListHeight, 200, and the drawing shows the first few.
  • Anything about how Revit will actually render this. See the note at the top.
