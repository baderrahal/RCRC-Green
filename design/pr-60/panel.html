Run says what is unfinished, the caption says title block, and the refresh line says what it could not file

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs and src/RcrcGreen.Revit/DrawingSheetRequestHandler.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show how the longer status line wraps at the pane's real width, or how a shut step's reason wraps under its header. The counts in the status line are the shape of the line and not a measurement.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

What changed

Three things a user can see. The step 4 control that picks the title block is captioned Title block, where it was captioned Type over a list of view type tick boxes and called a sheet type everywhere else. The RUN step, when nothing is asked for, says what in step 4 is unfinished: a sheet still needing its title block, rows still needing a name or a number, or both, where it used to tell somebody who had just added a sheet to add a sheet. And the refresh line ends with up to three clauses about what the read could not file: views whose PRX_Plot_ID holds something that is not a plot, names that are a plot in the wrong case, and schedules skipped at capture because their names do not parse. Each clause is absent when there is nothing to say.

Where the words come from

The RUN reason is PanelSteps, fed the rows short of a name or a number through SheetBatch.RowsShortOfANameOrANumber. The three refresh clauses are RefreshWords.ParameterNotAPlot, RefreshWords.WrongCase and RefreshWords.SchedulesNotCaptured, each reading a list the snapshot now carries. A wrong case name is said in IgnoredName's own words, which Shared already had. All of it is in Core with tests, so the panel and the handler format none of it.

Nothing else in the panel changed on screen

Under the surface, Scan Model still runs from the panel and writes the same report, less a sheet number tally that read 0 of 1385 parsed on every scan and a sheet name tally that could only ever read the same. The ribbon commands that were never reachable are gone. None of this has been through Revit.
