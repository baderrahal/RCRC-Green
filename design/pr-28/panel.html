KPI, first round: the ribbon and the pane

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/Kpi/KpiPanel.cs and src/RcrcGreen.Revit/RcrcGreenApplication.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show whether the second ribbon panel sits beside the first or wraps, how a two line button label breaks, what the real fonts come out as, whether a pane with an empty middle reads as finished or as broken, or whether the pane docks beside the Drawing Sheet pane or on top of it as a tab.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

The ribbon

One tab, two panels side by side. Drawing Sheet keeps its single button and is not touched. KPI is a new panel built to carry several buttons later and carries one this round. The Drawing Sheet button label is the one already shipped. Both are text only, no icon, which is how the first one shipped as well.

The pane, three states

Three things and no more: the model name with when it was last read, one button reading KPI Scan, and one status line. The middle is empty on purpose. The pane asks for the model name through its own external event the moment it is shown, so the first state lasts only until Revit answers. The words are all in KpiPaneWords in Core, with tests.

The button that cannot open its pane

When the KPI pane fails to register at startup, the button stays on the ribbon and Revit shows this when it is pressed. The Drawing Sheet pane goes through the same guard on its own, so neither can cost the other.

The KPI pane did not register when Revit started, so it cannot be opened. The Drawing Sheet
panel is unaffected. Restart Revit to try again.
