Underscores survive the caption, and the grid names all four sources

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. Whether any real view or scope box name on the first model holds an underscore is UNKNOWN, so the names below are made up to show the fault, and the page cannot show how WPF really drew the wrong one.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

What changed

Two things a user can see. Every tick box and button on the panel that carries a model name goes through the escape the KPI pane already had, so WPF no longer reads the first underscore in a plot, view type or view name as an access key marker, swallows it and underlines the next letter. And the sentence for a model with no plots, on step 1 and on the empty grid, names all four sources the plot list is the union of, where both copies still named two. Under the surface, six messages the panel formatted itself now live in PanelSteps with tests, a duplicate field in a captured schedule is written into the report rather than skipped, a plan asked of a section and a section asked of a plan are refused by naming the kind, and four descriptions of the tool that no longer existed are corrected.

Where the words come from

The escape is PaneLabel.Escaped in Core under Kpi, called across the fence rather than copied, with its test where it was. The sentence is PanelSteps.NoPlotsInTheModel, which step 1's reason and the grid's PanelSteps.NothingToDraw both read, and the other five moved messages sit beside it: the step 1 line, the scope box line, the two no plots ticked lines, the nothing to run line and the marked line. All with tests.
