Sheet numbers that will work

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show what a real editable ComboBox drops down like, whether a warning line under a box pushes the rows of the number table out of step, how long the list of free numbers actually is on a model with 1,385 sheets, or what the real fonts and spacing come out as.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

What changed

Three sheets were refused in one run, every one with a sheet numbered 010EA is already in this model. The refusal was right. The offer was wrong: the dropdown listed the sheet numbers already in use, so every entry in it was certain to be rejected. It lists free ones now, a number that will be refused says so under the box as it is typed, and step 5 counts them before the confirmation.

Where the numbers come from

All of it is SheetNumbers in Core. The dropdown list, the line under the box and the count in step 5 come from one place, so the panel can never say a number is fine while the run summary counts it. The count in step 5 and the line in step 4 are the same answer read twice, not two answers.

Three rules, each with a test. A number a sheet in the model already carries is refused. Two ticked plots given one number are both refused, and so are two separately described sheets that ask for one number, because they all go into one model. Already in the model is said before used twice, since both can be true at once and the model is the one somebody goes and looks at.

Nothing else in the panel changed

The grid, the sweeps, the shortened column headers and the legend are exactly as pull request 26 left them. This round is the number box and the run line.
