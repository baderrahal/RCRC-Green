Drawing Sheet panel layout

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show how Revit's theme will paint the panel, how a stretched Button looks against the dark theme's pane, what the real fonts and spacing come out as, whether a long view name fits the width of a docked pane, or whether the box characters in the grid have a glyph in the font Revit uses.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

The three states of one case line

LineWhat it means
+ C, ready to assign: 66 Closed and clickable. The tooltip says show the 66 views in this case, click one to open it.
- C, ready to assign: 66 Open. The 66 views are listed under it, indented, in plot order with the number read as a number, so DM-2 comes before DM-100.
+ A, name does not parse: 0 Disabled, because there is nothing to open. The tooltip says nothing in this case.
B, cannot hold a scope box: 102 Not a button at all. B is schedules and drafting views that have no scope box parameter, and nobody acts on that number.

One case is open at a time. Opening a second closes the first, and clicking an open case closes it. Six lists at once inside a docked pane is a scroll rather than a view.

When a delete is refused

A schedule that lost its plot filter is deleted again inside the same transaction. If Revit refuses that delete, the model holds a wrong schedule, and the status line says so before it says anything else.

RUN
1 WRONG SCHEDULE IS IN THE MODEL AND MUST BE DELETED BY HAND. 12 created, 1 not created. Press Refresh to see them. Report at C:\Users\bader\Desktop\RCRC-Green-Run_RCRC_NG05_2026-09-08_1407.txt and C:\src\RCRC-Green\reports\RCRC-Green-Run_RCRC_NG05_2026-09-08_1407.txt.

What changed from pull request 13

  • Five of the six scope box counts are buttons. Clicking one lists its views by plot and by name, with the scope box each one holds where there is one.
  • Clicking a view in a list opens it in Revit, through the external event, the same route the grid cells already use. The panel calls nothing itself.
  • B stays a plain line. It is 102 schedules with no scope box parameter.
  • A case with a count of 0 is drawn disabled rather than left looking clickable.
  • The counts and the lists both come from ScopeBoxCounts, so a list can never be a different length from the number above it. There is a test that walks all six cases and holds one against the other.
  • Assign is unchanged. It still acts on C alone, still asks first, still one transaction.
  • The status line after any report names every place the file really landed.
  • A run that left something wrong in the model says so in bold at the top of the status line, before the count of what was made.

What this mockup cannot tell you

  • Whether a stretched Button reads as a row or as a control on either Revit theme. WPF gives a Button its own chrome and PanelTheme does not paint it.
  • What a 66 entry list does to the height of a docked pane, and whether the scroll that follows is usable.
  • Whether a full view name fits the width. The line is set to clip rather than wrap, and that has not been seen.
  • Whether clicking a view in a case list activates it. The external event route is the one the grid uses and the grid has been clicked in Revit, but these buttons have not.
  • Any of the report text above. The write path has never run.
