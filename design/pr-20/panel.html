Drawing Sheet panel layout

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show how Revit's theme paints a docked pane, what WPF's own button chrome does to a step header, whether the frozen plot column really lines up with the scrolling columns beside it, what the real fonts and spacing come out as, or whether the box characters in the grid have a glyph in the font Revit uses.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

A step that cannot be used yet

Greyed out with one line saying why. A disabled control with no reason next to it tells somebody nothing, which is most of what made the old panel unreadable.

StepWhat it says
2  VIEW TYPESPick a plot range and tick at least one plot first.
3  MARKTick at least one view type in step 2. The grid has no columns until you do.
4  SHEETSThis model holds no sheets, so there is none to copy. Set one plot's sheet up by hand and press Refresh.
5  RUNMark a cell in step 3, or fill in a sheet number and name in step 4. Nothing is created until you do.
1  PLOTSThis model holds no plots. No view carries a PRX_Plot_ID and no view name gives one.

Every one of those lines is in PanelSteps in Core with a test on it, not written next to the control that shows it. So is every summary in every header above. The panel had two records of one fact three times running, and a count formatted where it is drawn is that shape again.

What changed from pull request 13

  • Five numbered steps, one open at a time, each carrying its own summary while shut.
  • A step that cannot be used is greyed out with one line saying why.
  • Picking a range opens step 2 by itself, once per read. Every other move is a Next button at the foot of the open step, or a click on any header. Nothing drags the user out of a step they are still working in.
  • A header strip at the top holding the model name, when it was last read, Refresh and Scan Model. Those belong to the document rather than to any one step.
  • One status line, docked at the bottom, in the same place whatever is open.
  • The grid has a legend, a frozen Use and Plot column, and shading on every other row.
  • A column header says plan, section or schedule in words. Italics alone said nothing.
  • One primary button, Run. Everything else is secondary.
  • The scope box counts moved inside step 5, because they act on the same ticked plots.
  • Every spacing and font size is in PanelMetrics, every colour in PanelTheme with a value per theme. The panel file names neither a number nor a brush.

What this mockup cannot tell you

  • Whether a step header, which is a WPF Button wrapped round a Border, reads as a header or as a control on either Revit theme.
  • Whether the frozen Use and Plot column really lines up with the scrolling columns. Both sides use one fixed row height for exactly that reason, and nobody has seen the result.
  • What a 17 row grid does to the height of a docked pane, and whether the two scrollbars that follow are usable together.
  • Whether the green Run button reads as primary or as an error on the dark theme.
  • Whether re-parenting the combo boxes and text boxes between redraws works. It is guarded in Reparented and WPF throws outright when it is not, so this is the one thing here most likely to be found on the first install.
  • Anything about the write path. No view, section, schedule or sheet has ever been created by this tool.
