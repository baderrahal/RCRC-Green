Drawing Sheet panel layout

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show how Revit's theme will actually paint the panel, how the Windows control chrome will look on the dark theme, what the real fonts and spacing come out as, or whether the box characters in the grid have a glyph in the font Revit uses.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

What changed from pull request 9

  • A Use column of tick boxes down the left of the grid. Everything ticked when a range is set, and changing the range sets them all back on. An unticked row is dimmed, stays on screen, and drops out of the scope box counts and out of anything that writes.
  • The range line counts ticked out of in range, not just in range.
  • A COLUMNS section holding every view type the model has, all ticked, with a count of how many are hidden. This replaces Add column, which started the grid empty and asked the user to build it one type at a time.
  • A SCOPE BOXES section showing all six case counts for the ticked plots before anything is pressed. It follows a tick straight away, because the counts come from the snapshot rather than from a new read.
  • Scan Model moved into the panel, under MODEL, because the ribbon is down to one button.
  • The status line carries the time of the read, so it is possible to tell whether a refresh actually ran.
  • The status line names how many views are titled for one plot and carry PRX_Plot_ID for another. That mismatch is what used to put a view in the wrong row.

What this page cannot tell you

  • Whether Revit paints anything of its own behind or around the pane that these colours sit badly against.
  • How the tick boxes, the buttons and the dropdowns look. They keep the Windows control chrome, which is drawn light on both Revit themes. Readable, and not a match for the dark theme.
  • Whether the font Revit gives the pane has a glyph for the three box characters. If it does not, they come out as empty rectangles and the tooltip is all that is left.
  • Real widths. The panel is docked right and the user can drag it to any width, so the column headers wrap differently from anything shown here. With every view type a column by default, a model holding dozens of types will need that horizontal scroll bar.
  • Whether the numbers in the case counts and the status line are anything like a real model. They are made up to show the shape of the line.
