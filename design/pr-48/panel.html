The plot a scan finds and the panel used to drop

This is a mockup drawn by hand from the code in src/RcrcGreen.Revit/DrawingSheetPanel.cs. It is not a screenshot.

Nothing on this page has been rendered by Revit or by WPF. It cannot show how the longer rows wrap at the pane's real width, what the tooltip really looks like, or how long the refresh takes now that it walks every element.

It exists so the layout and the wording can be read before someone spends an install on it. If anyone ever describes it as a screenshot, it has stopped being worth having.

What changed

The plot list is the union of every place a plot shows up: view names, PRX_Plot_ID on views, scope box names and PRX_Plot_ID on elements. It was built from views alone, so a plot existing only as a scope box with tagged elements, which is the plot with everything missing, never got a row and could never be ticked. Each row now carries a faint suffix when no view carries the plot, and the tooltip names every source. A plot with views says nothing, because the quiet case is the ordinary one.

Where the words come from

The suffix is PlotRecord.NoViewsInWords and the tooltip is PlotRecord.SourcesInWords, both in Core with tests, so the panel formats no rule of its own. The union itself is PlotRegistry.Build, which held the rule with tests all along and was called by nothing until this round.

Nothing else in the panel changed on screen

The grid, the sweeps, the sheet table and the scope box counts are exactly as the last round left them. Under the surface the plan preview now reads the same capturable schedule list the run reads, so step 5 can no longer promise a schedule the confirmation refuses.
