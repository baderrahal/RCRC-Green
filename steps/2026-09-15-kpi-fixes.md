# Running the four KPI fixes, 15 September 2026

For Bader, on Windows, in the order they happen. One action a step, and where a step carries a
command that is the one to paste. Nothing here was run in Revit by anybody, so every check below
is a check and not a claim.

What landed: the PDF text now fits its boxes, the Roads form takes Total Green cover like the
other two, the pane takes the team's plot list file, and a schedule row whose botanical name is a
dash counts as shrubs.

---

## 1. Pull main

In GitHub Desktop, with RCRC-Green open, press **Fetch origin** and then **Pull origin**. The
branch selector must read **main** before you pull.

## 2. Close Revit

Close Revit 2024 completely. The install overwrites the add-in's assemblies and Revit holds them
open while it is running.

## 3. Open the repository in VS Code

Open VS Code, then **File** then **Open Folder**, and choose the RCRC-Green folder GitHub Desktop
keeps.

## 4. Open a terminal in VS Code

**Terminal** then **New Terminal**. It opens in the repository root, which is where both commands
below expect to be.

## 5. Build the add-in in Release

The install script reads `src\RcrcGreen.Revit\bin\Release`, so that is the project to build and
Release is the configuration. Building it builds `RcrcGreen.Core` with it, through the project
reference.

```
dotnet build src\RcrcGreen.Revit\RcrcGreen.Revit.csproj -c Release
```

It must end with `Build succeeded.` and `0 Error(s)`. If it does not, stop here and send the
output.

The tests run on the GitHub test gate, on .NET 10, so this PC does not need the .NET 10 SDK
at all. This sheet asks for no test run of its own, which is why nothing here wants it.

## 6. Install it

```
.\install\install.ps1
```

It builds the `Addins\2024\RcrcGreen\` layout that the build does not, so copying the output
folder by hand leaves Revit unable to find the assembly. It ends by printing every file it
copied and `Restart Revit 2024 and look for the RCRC Green tab.`

## 7. Save the team's plot list

Put the 154 plots in a plain text file, **one plot per line**, and save it **outside this
repository**. Somewhere like:

```
C:\Users\<you>\Documents\RCRC\plot-list-154.txt
```

One plot per line, nothing else on the line:

```
DM-11
DM-12
FM-05
```

**The file must never go into the repository.** It is the client's own scope list and the
repository is public. Only a pointer to it is remembered, beside the installed add-in.

Edge spaces come off, blank lines are skipped, a plot listed twice is counted once and named with
both line numbers, and a line that is not a plot identifier is named with its line number. Nothing
is guessed out of a line that is not a plot.

## 8. Open the model in Revit

Start Revit 2024 and open the model.

## 9. Open the KPI pane

**RCRC Green** tab, then **KPI Checklist**.

## 10. Point the pane at the plot list

In the template block, on the **Plot list** line, press **Browse** and choose the file from step
7. Under it the pane says how many plots it read, over how many lines.

## 11. Read the plots

In the **Plots** block press **Read this model**. Nothing heavy runs without a press, so the plot
list cannot be ticked until this has finished.

## 12. Tick every workbook row

**THIS STEP IS EASY TO MISS AND IT COSTS THE WHOLE RUN.** In the template block, tick every
workbook row, which on the client's templates folder is all seven. A plot only goes into a
workbook whose row is ticked AND whose template is settled: `Settled()` at
`src/RcrcGreen.Revit/Kpi/KpiPanel.cs:1304` drops every other row, and the split at `:1296` runs
over what it hands back. **A ticked plot belonging to no ticked row is written nowhere.**

**If a row asks which of the two park templates it is, answer it.** The two park templates share
their main sheet name, so a file that settles nothing is ticked with no template and arms nothing
until you say which.

**These ticks live in the pane and nothing writes them down.** Closing Revit loses them, so this
step comes round again on every fresh start of the pane.

## 13. Press Tick the list

In the **Plots** block, beside **Select all** and **Clear**, press **Tick the list**. It replaces
every tick with exactly the plots the file names and forgets every plot you ticked or unticked by
hand, the same as those two do.

**THIS MUST BE THE LAST TICK ACTION BEFORE CREATE.** Ticking a template row ticks every plot that
belongs to it and unticking one takes them off again, both of them moving the plot ticks this step
has just set, at
`src/RcrcGreen.Revit/Kpi/KpiPanel.cs:1248`. So if you touch a workbook row after this, press
**Tick the list** again before you go on.

## 14. Read the named lines above Create

Before pressing anything, read the lines above the **Create** button. Every one of these is named
there rather than found in a report afterwards:

- a plot on the list the model does not name
- a plot listed twice, with both line numbers
- a line that is not a plot, with its line number
- a listed plot that would get no workbook or no PDF, with the reason

If a plot you expect is named there, fix it before pressing Create.

## 15. Press Create

Press **Create**. The progress window says which plot is being read and how far through it is.

# The five checks

One check a step. Each one is a thing to look at, not a thing to take on trust.

## 16. Every value inside its box on ANH-007-MO-100011

Open that plot's PDF. **Area, Total areas to be greened, and the tree and shrub counts must each
sit inside their box with nothing cut off at the edge and nothing drawn taller than the box.**

It read 2797.6 cut off and 0.0008 cut off before this round.

Then open the report and find **THE TEXT SIZES** near the top. It counts every value written, how
many kept the client's own size, how many were shrunk to fit, how many were capped at 10, how many
were held at 6 and still run over, how many had a font nobody could measure, and how many had no
`/DA` to change. **Only the last three carry a line naming the box**, and those are the boxes to
look at.

## 17. 0.001053 on ANH-007-ST-100308

Open that plot's PDF and read **Total areas to be greened**. It must read **0.001053**.

```
Canopy Area          984
Planting              69
Lawn Area          empty
Total Green cover  1,053      over a million is 0.001053
```

**It must NOT read 0.000984.** That is the canopy alone, which is what the Roads form took until
this round.

## 18. Existing Shrubs 231, Proposed 0, TOTAL 231 and Ground Cover 52 on HF-01

Open HF-01's PDF and read the four shrub boxes:

```
Existing Shrubs   231
Proposed Shrubs     0
TOTAL Shrubs      231
Ground Cover       52
```

231 plus 52 is 283, which is the group total its shrubs and lawn schedule prints. All four were
blank on the 08:38 run.

Then find **THE ROWS WHOSE BOTANICAL NAME IS A DASH, COUNTED AS SHRUBS** in the report. Every dash
row is named there with its plot, its row, its phase, its area and the box it went into, so you
can open the schedule at that row and see what was counted.

## 19. The vegetation numbers on one EP or FP plot

Open the PDF of any one EP or FP plot, which are the two that reach the **Parks** form, and read
the vegetation numbers: **Existing Trees, Proposed Trees, TOTAL trees** and the shrub rows under
them. Then find that plot's lines under **THE TEXT SIZES** in the report.

**THE PARKS ROWS SIT ABOUT HALF AS FAR APART AS THE OTHER FORMS' DO.** Measured off
`src/RcrcGreen.Core/Kpi/PdfForms.cs:276` to `:278`, the three tree rows are at y 611.3, 601.0 and
590.6, which is 10.3 and 10.4 apart. The open spaces form's same three rows, at `:310` to `:312`,
are at 449.2, 428.9 and 408.9, about twice that.

The height rule takes 2 pt off the top and 2 pt off the bottom of the box, so a Parks box as tall
as the gap to its neighbour leaves about 6.3 pt, which is barely over the 6 pt floor, and a box any
shorter lands at the floor. **So expect some of these numbers to be named held at 6 while they
still sit inside their box.** That line says the text did not fit at 6 by the WIDTH rule as well,
so what to look at is the box itself.

**WHAT THE BOXES ARE REALLY THAT TALL IS UNKNOWN HERE.** The row positions above are measured and
recorded in this repository. The heights are not, because no client PDF is in it and none ever
will be, so a number for the height would be a guess. This check is what measures them: read the
size the report says each one came out at and send those lines back.
